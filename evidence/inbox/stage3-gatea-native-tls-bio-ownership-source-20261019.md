## Pinned lifetime rules relevant to D0 L3

1. **SSL configuration remains borrowed.** [Pinned mbedTLS `ssl.h` L1900–1912](https://github.com/Mbed-TLS/mbedtls/blob/6cc42afad309e861f4c07e6f106e2ab14a9cb8e5/include/mbedtls/ssl.h#L1900-L1912) states `mbedtls_ssl_setup()` does not copy configuration and it must not be modified/freed during a live session. [CA chain configuration L3423–3435](https://github.com/Mbed-TLS/mbedtls/blob/6cc42afad309e861f4c07e6f106e2ab14a9cb8e5/include/mbedtls/ssl.h#L3423-L3435) accepts an external trusted chain pointer. **Design inference:** one attempt owner must keep config and CA lifetime valid until SSL no longer uses them; no runtime proof yet.
2. **BIO context is not automatically owned by TLS.** [`mbedtls_ssl_set_bio()` L2129–2163](https://github.com/Mbed-TLS/mbedtls/blob/6cc42afad309e861f4c07e6f106e2ab14a9cb8e5/include/mbedtls/ssl.h#L2129-L2163) stores a callback context and send/recv callback functions; nonblocking `f_recv` is explicitly supported. The pinned [Espressif backend L182–190](https://github.com/espressif/esp-idf/blob/7101770dc6db2667b3c477cc31365dd1acd6db4e/components/esp-tls/esp_tls_mbedtls.c#L182-L190) uses `&tls->server_fd`. A private BIO owner must outlive all active TLS calls and cannot be a freed stack object after a detached operation.
3. **WANT retry preserves exact write arguments.** [`mbedtls_ssl_write()` L5059–5089](https://github.com/Mbed-TLS/mbedtls/blob/6cc42afad309e861f4c07e6f106e2ab14a9cb8e5/include/mbedtls/ssl.h#L5059-L5089) requires retrying with the same arguments after WANT_READ/WANT_WRITE, including buffer pointer and length. Only a positive returned count permits advancing the offset; a possibly delivered HTTP command is not retried as another attempt. Accepted D2-P0-T **26/26 SYNTHETIC_PASS** checks bytes/offset but not native buffer-pointer identity or lifetime.
4. **Close notify is not socket close/quiescence evidence.** [`mbedtls_ssl_close_notify()` L5127–5139](https://github.com/Mbed-TLS/mbedtls/blob/6cc42afad309e861f4c07e6f106e2ab14a9cb8e5/include/mbedtls/ssl.h#L5127-L5139) can return WANT_READ/WANT_WRITE. [`mbedtls_ssl_free()` L5314–5319](https://github.com/Mbed-TLS/mbedtls/blob/6cc42afad309e861f4c07e6f106e2ab14a9cb8e5/include/mbedtls/ssl.h#L5314-L5319) frees SSL context internals but returns no socket-close acknowledgment. The pinned Espressif example calls close_notify without checking its result, then resets the session and frees the network context. This **is not** an L3 teardown witness. Native lwIP close failure and DNS callback lifetime remain independently unproven.

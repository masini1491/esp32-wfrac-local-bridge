## Specific source conclusions

1. **Existing ESP-TLS async is NOT nonblocking hostname resolution.** `esp_tls_conn_new_async()` enters `esp_tls_low_level_conn()` → `tcp_connect()` → `esp_tls_hostname_to_fd()` → synchronous `getaddrinfo()`. `esp_tls_set_conn_sockfd()` only assigns `tls->sockfd`; the exposed setter by itself does NOT prove an officially supported, already-connected client TLS handshake path that bypasses `tcp_connect()`. Source: [esp_tls.c#L221-L248](https://github.com/espressif/esp-idf/blob/7101770dc6db2667b3c477cc31365dd1acd6db4e/components/esp-tls/esp_tls.c#L221-L248), [#L386-L403](https://github.com/espressif/esp-idf/blob/7101770dc6db2667b3c477cc31365dd1acd6db4e/components/esp-tls/esp_tls.c#L386-L403), [#L489-L531](https://github.com/espressif/esp-idf/blob/7101770dc6db2667b3c477cc31365dd1acd6db4e/components/esp-tls/esp_tls.c#L489-L531), [#L610-L618](https://github.com/espressif/esp-idf/blob/7101770dc6db2667b3c477cc31365dd1acd6db4e/components/esp-tls/esp_tls.c#L610-L618), [#L769-L777](https://github.com/espressif/esp-idf/blob/7101770dc6db2667b3c477cc31365dd1acd6db4e/components/esp-tls/esp_tls.c#L769-L777).
2. **An actual async DNS option exists, but its callback lifetime is unproven for this synchronous adapter.** The pinned lwIP raw `dns_gethostbyname_addrtype()` expressly returns `ERR_INPROGRESS` with later `dns_found_callback`. The public pinned `lwip/dns.h` examined does not declare a per-request cancellation function. The DNS request table stores the callback and caller argument until callback processing. An adapter may NOT pass a stack/caller-owned pointer that could expire at timeout; any bounded owner/retained request/callback quiescence strategy requires separate design, test and context/thread-affinity verification. Source: [dns.c#L1669-L1740](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/core/dns.c#L1669-L1740), [dns.c#L1525-L1560](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/core/dns.c#L1525-L1560), [dns.c#L1049-L1081](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/core/dns.c#L1049-L1081), [dns.h#L95-L113](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/include/lwip/dns.h#L95-L113).
3. **Physical IP and certificate/SNI name are distinct.** `set_client_config()` chooses caller-supplied `cfg->common_name` if present, otherwise connection `hostname`; it passes the selected string to `mbedtls_ssl_set_hostname()`. `skip_common_name=true` disables BOTH hostname matching and SNI and is unacceptable as a silent workaround. The project TLS owner already records some observed self-signed WF-RAC HTTPS certificates with IP/CN mismatch. Therefore a literal-IP connection is not automatically authenticated: require explicitly trusted peer identity, usable PEM trust and correct name/certificate evidence; none is hardware-confirmed for the proposed adapter. Source: [esp_tls_mbedtls.c#L913-L940](https://github.com/espressif/esp-idf/blob/7101770dc6db2667b3c477cc31365dd1acd6db4e/components/esp-tls/esp_tls_mbedtls.c#L913-L940), [esp_tls.h#L198-L207](https://github.com/espressif/esp-idf/blob/7101770dc6db2667b3c477cc31365dd1acd6db4e/components/esp-tls/esp_tls.h#L198-L207), [local TLS policy](https://github.com/masini1491/esp32-wfrac-local-bridge/blob/c2efa3ffa83d7fac901f19dc860aebb284a5a5fa/docs/references/topics/tls-transport.md).
4. **Nonblocking socket does not prove bounded cleanup.** `esp_tls_conn_destroy()` frees TLS and calls `close(tls->sockfd)`. In pinned lwIP, `lwip_close()` calls `netconn_prepare_delete()`, which can enter `netconn_apimsg`. The TCP close code explicitly handles `ERR_MEM` by waiting and states this may occur **even for nonblocking netconns**. L1 cooperative I/O budget is separate from hard wall-clock caller-return, cancellation and L3 quiescence; no source proof of a universal cleanup bound. Source: [esp_tls.c#L180-L195](https://github.com/espressif/esp-idf/blob/7101770dc6db2667b3c477cc31365dd1acd6db4e/components/esp-tls/esp_tls.c#L180-L195), [sockets.c#L817-L842](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/sockets.c#L817-L842), [api_lib.c#L195-L225](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/api_lib.c#L195-L225), [api_msg.c#L1068-L1110](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/api_msg.c#L1068-L1110).

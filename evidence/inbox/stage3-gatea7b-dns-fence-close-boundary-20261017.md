**Observation date:** 2026-10-17 (Asia/Taipei). **Repository baseline:** `main@7a82372af8deed0e7a7ddf319553969c07f0dc47`. **Research only; no test, SDK, production, firmware, network or hardware mutation.**

## Question and evidence boundary

After the integrated A7b real Linux SDK DNS-handler test (PR #12), can one prove that a completed callback's owner token is safe to reuse, and can the same proof establish a whole DNS→TCP→TLS→HTTP→cleanup hard deadline? **These are independent questions.** No new implementation admission is inferred from this read-only study.

## Pin-verified facts

1. **DNS request clear follows invocation** (`SOURCE_CONFIRMED`). In pinned `dns_call_found`, the user `found` callback returns before `dns_requests[i].found=NULL` executes; in the coalesced branch a loop walks request entries one at a time. The request entry also stores `arg`; clearing `found` does not zero `arg` in this function. This makes mere `DNS_found_exit_marker` insufficient for a safety claim, and a dangling raw pointer may remain in a dormant slot until overwritten. [[pinned dns.c L1049–1081]](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/core/dns.c#L1049-L1081).
2. **A successfully enqueued deferred TCPIP callback executes as a later mailbox message only when the TCPIP task resumes processing** (`SOURCE_CONFIRMED`, bounded by scheduler/queue assumptions). `tcpip_thread` handles one message synchronously, with a separate `TCPIP_MSG_CALLBACK` case. `tcpip_try_callback` uses `memp_malloc` and `sys_mbox_trypost`, and returns `ERR_MEM` if either fails. An `ERR_OK` admission is not proof that the fence ran, nor a wall-clock bound; no queued execution occurs if the core task never exits its current callback. [[tcpip.c L127–150]](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/tcpip.c#L127-L150), [[L199–203]](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/tcpip.c#L199-L203), [[L350–369]](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/tcpip.c#L350-L369).
3. **Previously admitted real SDK handler evidence** (`SDK_DNS_HANDLER_RUNTIME_CONFIRMED` only for the isolated zero-egress Linux fixture). Independent CI [run 38672587090 / A7b job 116218899349](https://github.com/masini1491/esp32-wfrac-local-bridge/actions/runs/38672587090) logs: original `dns_send` → `__wrap_udp_sendto` relocation, zero-egress pre-execution gate and 7/7 cases PASS. In `success` and `error`: `registration_INPROGRESS → original_dns_recv_enter → DNS_found_enter → fence_admitted → DNS_found_exit_marker → original_dns_recv_returned → deferred_fence`. In duplicate hostname: both distinct callbacks finish before both deferred fences. In `fence-error`: `fence_rejected` / `ERR_MEM`, no fence. In `exhaust`: multiple registered retained owners and final `ERR_MEM`, no recycle. In `late`: 50 ms caller wait expires yet callback and fence occur later. See [test fixture](../../tests/espidf_dns_probe/main/dns_lifecycle.cpp) and [README](../../tests/espidf_dns_probe/README.md).
4. **What A7b did not observe:** private `dns_requests[].found` directly (private static state), actual owner release/reuse/free, a permanently blocked callback or fence, native DNS/UDP ingress, natural DNS timer expiry, TLS/socket execution, or any caller-return/close duration guarantee. The fixture keeps owners static until exit; process exit is not explicit resource quiescence. Source + ordering is conditional evidence of clearing for completed callbacks, **not** a new token-reclaim runtime PASS.
5. **Close is a separate potential blocking boundary** (`SOURCE_CONFIRMED`). `lwip_close()` calls `netconn_prepare_delete()` before releasing the socket; the latter invokes `netconn_apimsg(lwip_netconn_do_delconn, ...)`. The pinned TCP close path can retry after `ERR_MEM` and arrange a 500 ms TCP poll, and completion signals the waiting API-message semaphore only after the close branch settles. Configured retry/poll counters or `send_timeout` are not a hard synchronous caller-return upper bound under arbitrary TCPIP scheduling stalls. This is a **source-backed limitation**, not an observed unbounded live close. [[sockets.c L817–854]](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/sockets.c#L817-L854), [[api_lib.c L195–224]](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/api_lib.c#L195-L224), [[api_msg.c L1232–1250]](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/api_msg.c#L1232-L1250), [[L1064–1148]](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/api_msg.c#L1064-L1148).

## Narrow decision matrix (research conclusion, not permission to implement)

| Path | A7b/source-supported conditional rule | What is still missing | Disposition |
| --- | --- | --- | --- |
| Normal SDK DNS completion | Completed original callback followed by **executed** fence in the same serialized TCPIP task provides a source-grounded *post-clear barrier* for that particular callback | Direct private slot read unavailable; no explicit owner free/reuse run; must prove no other code references token | Candidate for isolated **test-only** positive reuse experiment; no production admission |
| Coalesced duplicate | Both callbacks return before either queued fence, for the tested configuration; separate arguments remain distinct | Multi-request callback lifetime and reuse sequence not tested | Retain owners; test distinct tokens and no cross-owner release |
| Fence enqueue `ERR_MEM` | No fence admitted, and no post-clear evidence from that callback's fence | Safe retry after callback exits requires another serialized barrier and bounded retry policy | Retain/quarantine token; fail closed; no reclaim claim |
| Callback never returns / never arrives | No reliable callback completion or fence execution | Scoped cancellation, bounded eventual reclamation | Quarantine to bounded capacity, then `STOP / unavailable`; not a hard deadline solution |
| TCP close / TLS cleanup | Pending API-message and TCP polling may delay cleanup | Independently bounded close/free and caller-return under pinned SDK | Gate A whole-attempt hard deadline remains `UNPROVEN` even if DNS reuse is shown |

## Proposed *separate Codex approval* for next material test-only evidence

**Do not implement under this research checkpoint.** Only if separately approved, extend the existing isolated zero-egress Linux SDK fixture (not production/firmware/SDK fork) in `tests/espidf_dns_probe/**`, with minimal path-selective GitHub CI registration only if genuinely needed:

1. **Preserve existing pre-execution zero-egress gate** (effective ELF wrapper call, no live netif, wrapper-only smoke, strict no-send, matched pinned config) and 7/7 A7b regression. No socket, real DNS traffic, credential, device, SDK patch, QEMU or hardware.
2. **Positive controlled case:** allocate two distinguishable bounded static pool owners; complete the first registered DNS lookup via genuine injected SDK handler; enqueue and observe the real fence; only then mark the first token eligible to recycle. Re-register with an unrelated name and new generation ID, then repeat callback/fence. Require exact callback identity, no stale-generation callback, no UAF and a consistent complete event ordering; record that private `found=NULL` was **inferred from pinned source plus same-core ordering**, not independently read.
3. **Negative cases:** duplicate hostname callback args; expiration before callback; fence `ERR_MEM` and queue full; delayed/no fence, absent callback until capped test STOP, and pool exhaustion. Never free/recycle on `ERR_OK` queue admission alone. Distinguish retained/quarantined from safely recycled; do not simulate a missing real SDK callback with a fake event.
4. **Proof exit:** exact SHA/build configuration, 0 egress proof, negative outcomes, possible safe local pool-reuse behavior, and explicit `NOT_RUN / UNPROVEN` for infinite callback stall and close cleanup. No Stage 3 Gate A feasibility pass, no Gate B or SDK production transport mutation. If private-state semantics or runtime execution cannot support a defensible reuse proof without SDK instrumentation, STOP and report `NO_GO` rather than manufacturing a pass.

**Current recommendation:** The useful next check is *bounded completed-DNS owner reuse*, not yet another general synthetic deadline model. Even a PASS there cannot make the original universal synchronous DNS→TCP→TLS→HTTP→close deadline true; that broader capability requires a separate architecture/SDK/caller-contract decision.

## 1. Verified source call graph; not runtime execution

1. **BSD/socket:** [pinned sockets.c](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/sockets.c#L817-L855) `lwip_close(s)` validates `get_socket`, invokes `netconn_prepare_delete`, and on non-`ERR_OK` maps errno, calls `done_socket`, and returns `-1`; only success reaches `free_socket(sock,is_tcp)` then returns 0. This does **not** prove that the failed descriptor is always reusable or that a successful close reclaimed a TCP PCB.
2. **Netconn operation:** [pinned api_lib.c](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/api_lib.c#L195-L250) `netconn_prepare_delete` uses `netconn_apimsg(lwip_netconn_do_delconn,...)`; its own comments explicitly allow TCP PCBs to remain in wait states after successful API return. `netconn_apimsg` passes through `tcpip_send_msg_wait_sem` and returns the operation's `api_msg.err` when the wrapper succeeds.
3. **Pending/error differentiation:** [pinned api_msg.c](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/api_msg.c#L1024-L1250) can record `ERR_INPROGRESS` for pre-existing netconn work, handle close attempts, retry internal `ERR_MEM` via poll/sent callback, or abort after its internal timeout path. When asynchronous close is pending, the internal API message may remain outstanding and eventual signalling occurs later. These are code paths, **not** proven outcomes under R2-B's single successful socket fixture.
4. **Underlying TCP close:** [pinned tcp.c](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/core/tcp.c#L330-L495) `tcp_close_shutdown_fin` may see `tcp_send_fin() == ERR_MEM`, set `TF_CLOSEPEND`, and **return `ERR_OK`** to prohibit further caller use while the timer retries. Consequently, a socket-layer 0 return neither excludes historical internal memory pressure nor proves immediate FIN emission/PCB reclamation. Do not infer `TF_CLOSEPEND` from an API return or inspect mutable private PCB from an unsupported context.
5. **No universal caller-return deadline:** [pinned tcpip.c](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/tcpip.c#L441-L464) non-core-locking mailbox path uses `sys_mbox_post` then `sys_arch_sem_wait(sem,0)`, an untimed semaphore wait. The internal close retry default/linger/send timeout is **not** an end-to-end hard bound on this caller. A watchdog can only document *no observed return within the observation window*; external termination is not SDK cancel/quiescence or safe resource cleanup.
6. **Separate application callback lifetime:** [pinned tcpip.c callback dispatch](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/tcpip.c#L190-L215) runs posted callbacks on TCPIP thread. R2-B's test-owned independent barrier ACK witnesses a **previous** application callback returned on that serialized thread, not the barrier callback's own return and not all SDK callbacks/workers.

## 2. R2-C observation classifications (design, no executions)

| Event category | What a future authorized test could observe | Conservative application-owner outcome | Forbidden inference |
| --- | --- | --- | --- |
| `RETURN_OK` | Exact close-enter / caller-return code 0 / errno / elapsed + token/generation | `RELEASE_ELIGIBLE` **only** after independently verified all test-owned callbacks ACKed and tracked borrows/registrations cleared; logical release only | FIN flush, PCB/TIME_WAIT free, global SDK quiescence, bounded future calls |
| `RETURN_ERROR` | Actual close-return `-1`, errno, descriptor probe where independently safe | `CLOSE_ERROR_RETAINED`, no automatic second close or free; reconcile actual descriptor disposition separately | Error means descriptor surely open, or second close safe |
| `NO_CALLER_RETURN` | Separate attempt-start evidence, monotonically elapsed observer window, missing caller-return event | `WAIT_UNKNOWN_RETAINED`; watchdog outcome `TEST_TERMINATION` only | Treat timeout as `lwip_close=-1`, an SDK cancellation, or safe cleanup |
| `CALLBACK_PENDING` | Post result, callback enter/last owner access, independent barrier entry/ACK, current generation | Retain owner while any application-owned callback completion remains unacknowledged | Posting success, exit-intent or callback-internal flag means return |
| `CALLBACK_POST_ERROR` | Actual `tcpip_try_callback` non-`ERR_OK`; no proven queued token | Keep owner/context until no in-flight test registration/borrow and safe close provenance | All submissions fail as `ERR_MEM`, or inject fake error and call it SDK proof |
| `INTERNAL_CLOSEPEND` | Only pinned source shows `TF_CLOSEPEND` path; no public BSD-socket event directly exposes it here | Label `SOURCE_POSSIBLE / NOT_OBSERVED` | Treat a fast close 0 as proof this path occurred or did not occur |

Minimum future trace identity: exact repository+SDK refs, generated lwIP configuration, test run ID, immutable `owner_token`/`generation`/`callback_token`, caller/task identity, `close_attempt`, `close_return` or `close_unreturned_at_watchdog`, result/errno/elapsed, descriptor probe with safety provenance, separate `callback_post_attempt`, `callback_post_return`, `callback_enter`, `callback_last_owned_access`, `barrier_ack`, borrow and registration snapshot, `owner_release` only when qualified, and `TEST_TERMINATION` separately. Include event sequence and `CLOCK_MONOTONIC` timestamp: causal sequence must strictly increase; equal ticks may be legal for ordinary events; release must occur strictly later than qualifying completion events when that is the test contract. Failure paths must retain static backing storage and raw partial trace, never blindly retry or dereference presumed freed context.

## 3. What is and is not feasible without new authority

- **R2-C0 — this study: COMPLETED / SOURCE_REVIEWED.** Source-to-event observability map and anti-overclaim/STOP criteria recorded. No new tests.
- **R2-C1 — optional future purely offline test-owned observation/negative trace contract:** independently exercise `RETURN_ERROR`, `NO_CALLER_RETURN`, `CALLBACK_PENDING`, synthetic `EBADF`, stale generations, duplicate close and logical owner release rejection. Evidence tier at most `SYNTHETIC_APP_OWNER_GUARD`; this cannot substantiate a native SDK error. Any new source, runner or repo mutation requires separate scoped user authority and an approved clean main workspace.
- **R2-C2 — optional future pinned native natural-error observation:** first source-check whether a bounded **naturally occurring**, non-forced close delay/error can be observed safely under the prior `--network none` test contract, without SDK/private PCB modification or alternate workers. A natural scenario might not produce an error; `NOT_OBSERVED` must not be rewritten as `PASS`. Native Runtime, Docker and test-only source still require separate explicit approval, clean workspace, environment isolation and independent trace review.
- **R2-C3 — intrusive `ERR_MEM`/private-PCB fault injection: NOT ADMITTED / NOT RECOMMENDED as a default next step.** Modifying pinned SDK or faulting TCPIP thread changes what is under test and could invalidate source identity, callback lifetime and isolation. No implied permission; would need independent research and safety/governance authorization.

## 4. Architectural disposition and STOP

The production adapter [esp_http_transport.cpp](../../components/wfrac_transport_espidf/src/esp_http_transport.cpp) still uses synchronous `esp_http_client_perform()` plus `esp_http_client_cleanup()` and a stack-local `ResponseCollector`; it does not establish a controllable monotonic total-attempt budget. A separate worker/watchdog that abandons the caller and destroys the collector/client would risk use-after-free while the SDK may still reference them. Preserving owner conservatively prevents that error but **does not solve arbitrary resource retention or enforce global hard caller-return**. A publicly observed callback barrier is only application-owned callback evidence, not TCP/TLS/global worker reclamation.

## Binding project contract — what D0 actually accepts

Canonical [`TASKS.md` D0 accepted 2026-10-12](../../TASKS.md) (the exact heading `D0 — layered Deadline acceptance contract`), corroborated by [accepted D1 host suite `test_deadline_d1.cpp`](../../tests/host_cpp/test_deadline_d1.cpp):

- **L1** is a **shared monotonic aggregate budget for controllable I/O**, recomputed before each controllable wait, after `EINTR/EAGAIN/WANT_READ/WANT_WRITE`, with slow-trickle resistance, overflow/clock regression fail-closed. D0 **expressly refuses a hard total `perform()` caller-return, unpreemptible lwIP/crypto/SDK execution, scheduler starvation or cleanup bound without independent proof**. This prohibition is a *claim boundary*, not a requirement that must somehow be established before any D0-compatible design is considered. D1's synthetic `L1/nonpreemptible operation counterexample` (lines 446–449) accepts a simulated operation ending at clock=17 with deadline=10 as `timeout`, not an alleged caller-return bound.
- **L2** requires fail-closed, atomic published output, `body_size=0` on failure, one physical attempt, no re-drive of a possibly-delivered write, no TLS downgrade, and error taxonomy preservation. If execution is blocked in an SDK API, the synchronous caller cannot publish a timeout until control **actually returns**; D0 does not require a separately preemptive response path. D1's `L2/success atomic only after quiescence` (lines 450–455) is a synthetic correctness witness only.
- **L3** requires one owner of socket/TLS/parser/BIO/callback/buffer with `ACTIVE→TERMINAL_DECIDED→STOPPING→QUIESCENT→RELEASED`, no in-flight use or caller-buffer UAF before release, and fail-closed quarantine/STOP of conflicting attempts when quiescence is unknown. Safe synchronous cleanup **may overshoot L1** and does not constitute hard-deadline PASS. D1 explicitly includes `L3/timeout cleanup overrun counterexample, safe return not hard deadline` (lines 530–533): 10-budget + 25 cleanup → clock 35, `timeout`, `released`; plus `L3/complete-before-deadline cleanup later` (535–538) differentiating I/O outcome from caller return. D1 additionally models in-flight callback quarantine before release (507–513) and close-failure no-release/no-next-attempt (524–528). None is real SDK quiescence proof.
- D0 **does not explicitly stipulate literal zero residual TCP PCB protocol wait states before return**. It enumerates application-owned resources/callback/buffers and their safe release. Pinned [lwIP `api_lib.c` L185–233](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/api_lib.c#L185-L233) explains connected PCBs may remain in normal waitstates following successful netconn deletion; [`tcp.c` L1451–1480](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/core/tcp.c#L1451-L1480) shows TIME_WAIT timer collection. **Interpretation, NOT a new accepted architecture change:** distinguish application ownership and retained unsafe references (L3) from protocol-owned PCB close states. Exact allowable residual PCB/memory budget, if materially required, still needs an explicit engineering acceptance choice; do not silently waive actual callback/handle quiescence.

The existing D0 already admits **controlled-I/O deadline + post-I/O safe cleanup, with honest late-return disclosure**, while still requiring L2 atomicity, L3 safe ownership/quarantine, public endpoint compatibility and TLS trust.

## Verified upstream semantics

1. **Project-actual default core-locking differs from generic lwIP.** ESP-IDF 6.0.2 `components/lwip/Kconfig` declares `CONFIG_LWIP_TCPIP_CORE_LOCKING` default `n`, while its port `lwipopts.h` maps disabled config to `LWIP_TCPIP_CORE_LOCKING=0`. Project-tracked `firmware/wfrac_bootstrap_probe/sdkconfig.defaults` does not override it; project compile CI pins `espressif/idf:v6.0.2` but actual generated `sdkconfig` per cell was **not** independently inspected here. The effective setting is build-scoped, not a universal assumption. Sources: [IDF Kconfig L29-L40](https://github.com/espressif/esp-idf/blob/7101770dc6db2667b3c477cc31365dd1acd6db4e/components/lwip/Kconfig#L29-L40), [IDF port lwipopts L37-L63](https://github.com/espressif/esp-idf/blob/7101770dc6db2667b3c477cc31365dd1acd6db4e/components/lwip/port/include/lwipopts.h#L37-L63), project [defaults](https://github.com/masini1491/esp32-wfrac-local-bridge/blob/f74bf38edfd79ac9ba05ff6f513df2d8ecd5df31/firmware/wfrac_bootstrap_probe/sdkconfig.defaults), [compile workflow](https://github.com/masini1491/esp32-wfrac-local-bridge/blob/f74bf38edfd79ac9ba05ff6f513df2d8ecd5df31/.github/workflows/esp-idf-compile.yml).
2. **`tcpip_callback()` is not a hard bounded dispatch.** Pinned `src/api/tcpip.c` uses `sys_mbox_post()` and explicitly documents that the call can block until the item is posted. `tcpip_try_callback()` uses `sys_mbox_trypost()` and returns `ERR_MEM` if no message slot/queue capacity exists. Both store a caller-provided `void* ctx`, which must remain alive until actual dispatch or proven failure. `tcpip_callback_wait()` is explicitly synchronous and is not a substitute for a deadline-safe async submission. Sources: [tcpip.c L318-L369](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/tcpip.c#L318-L369), [tcpip.c L579-L622](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/tcpip.c#L579-L622).
3. **Critical ordering behind A3's fake `callback_return`.** Pinned DNS `dns_call_found()` invokes `(*dns_requests[i].found)(..., dns_requests[i].arg)`, **then** clears `dns_requests[i].found = NULL`, and handles possible DNS PCB cleanup. Therefore setting the owner state to `QUIESCENT` **inside the user DNS callback** cannot itself prove lwIP has finished consuming its registration. The fixed A3 fake scheduler's `callback_return` is an oracle controlled by a test, not a real SDK event. Source: [dns.c L1049-L1112](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/core/dns.c#L1049-L1112).
4. **A possible deferred post-callback fence exists, conditional on successful enqueue.** The TCPIP thread handles `TCPIP_MSG_CALLBACK` by calling the registered function in its own event dispatch; the main thread loop processes these messages sequentially. The **hypothesis** is to issue `tcpip_try_callback(fence, stable_ctx)` from the DNS callback; if it returns `ERR_OK`, the fence event is queued for future dispatch **after the current DNS callback and lwIP's enclosing DNS processing return**, provided the relevant DNS invocation is under the TCPIP thread/core serialization contract. This is a source-supported conditional ordering argument, **not a verified public DNS cancellation / quiescence API or proof against all supported configurations or thread schedules**. Source: [tcpip.c L106-L197](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/tcpip.c#L106-L197), [tcpip.c L331-L369](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/tcpip.c#L331-L369), [lwipopts.h L37-L63](https://github.com/espressif/esp-idf/blob/7101770dc6db2667b3c477cc31365dd1acd6db4e/components/lwip/port/include/lwipopts.h#L37-L63).
5. **Deadline/nonarrival and close risks remain.** Raw DNS callback is registered at `ERR_INPROGRESS` with a caller-provided pointer; no reviewed public per-registration cancellation API. Callback depends on DNS retries/TCPIP timers; late or never-arriving callback requires retained or safe externally owned context, not stack storage. `dns_clear_cache()` can invoke unrelated callbacks and is NOT scoped cancellation. ESP-TLS `esp_tls_conn_destroy()` calls `close()`, which enters lwIP `netconn_prepare_delete()` / TCPIP API and may wait when close returns `ERR_MEM`, even for nonblocking sockets. A successful callback fence is **not** a proof of a hard bound on DNS, TLS, socket close, total `ITransport::perform()` return or memory recovery. Sources: [dns.c L1525-L1659](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/core/dns.c#L1525-L1659), [dns.c L1675-L1826](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/core/dns.c#L1675-L1826), [dns.c L403-L420](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/core/dns.c#L403-L420), [esp_tls.c L180-L195](https://github.com/espressif/esp-idf/blob/7101770dc6db2667b3c477cc31365dd1acd6db4e/components/esp-tls/esp_tls.c#L180-L195), [api_lib.c L195-L225](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/api_lib.c#L195-L225), [api_msg.c L1070-L1100](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/api_msg.c#L1070-L1100).

## Minimal bounded design candidate (REFERENCE-ONLY; NOT ADOPTED)

- Keep a stable, app-owned `resolver_slot` + `callback_token` separate from the synchronous caller stack/buffer. Reserve ownership before any `tcpip_try_callback` posting. A request entry must remain live until both the initial registration decision and any pending DNS callback/fence references are demonstrably inactive. Expiring user requests must fail closed without reusing their memory.
- Submit the DNS-registration function through an async `tcpip_try_callback` using the same stable owner; it invokes raw `dns_gethostbyname_addrtype()` only in the correct TCPIP core context. Explicitly handle `ERR_OK` (immediate) vs `ERR_INPROGRESS` (callback registered) vs immediate `ERR_MEM/ERR_ARG/ERR_VAL`, and account for potential synchronous hooks/ordering before changing token state. A successful submission does not mean the function has executed.
- On the actual DNS callback, copy only a bounded address/result into owner storage, reject all late/expired generations and never touch caller buffers. Optionally queue a separate **post-callback fence** using `tcpip_try_callback`. Treat `ERR_OK` as a pending *candidate* acknowledgement; only when that fence executes under proven core serialization may owner consider its callback-return/quiescence decision. **On `ERR_MEM`, do not free/reuse the token**; investigate a separately owned retry/quiescence protocol that does not rely on any pointer already released.
- Preserve finite slot/token capacity and explicit exhaustion semantics. In contrast to A3's permanently retired token for every successful generation, **conditional token recycling after independently proven quiescence may be possible**, but no recycling on mere callback entrance or local `callback_return` flag. If the raw DNS callback never occurs, or fence never executes, bounded memory may still lead to loss of service. Do not call this eventual reclamation.
- Preserve logical hostname, TLS chain/identity/SNI, one-physical-attempt, `timeout_ms`, SchemePolicy and existing software security policy. Do NOT enable TLS hostname skipping, replace DNS with numeric-only API, call unsafe PCB abort, or wrap a potentially blocking `close()` into an unproven hard deadline.

## Pinned-source feasible design

1. Pinned [esp-lwIP `dns.c` L849-969](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/core/dns.c#L849-L969) has a single direct outbound packet API in `dns_send()`: `udp_sendto(dns_pcbs[pcb_idx], p, dst, dst_port)` at L957, followed by `pbuf_free(p)`. Pinned `dns_enqueue()` synchronously enters that path before returning `ERR_INPROGRESS`. Source-level candidate: GNU-linker `-Wl,--wrap=udp_sendto` with test-only `extern "C" __wrap_udp_sendto(...)`, bounded copy of query pbuf/PCB/destination, recording attempted sends and returning a controlled `err_t`; **NEVER** call `__real_udp_sendto` or any socket/network output. Espressif's [pinned Linux lwIP CMake L228-241](https://github.com/espressif/esp-idf/blob/7101770dc6db2667b3c477cc31365dd1acd6db4e/components/lwip/CMakeLists.txt#L228-L241) already uses GNU linker `--wrap` for other POSIX functions, supporting toolchain plausibility, not proof that the new wrapper is effective.
2. Actual [`lwip/udp.h` L77-115](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/include/lwip/udp.h#L77-L115) exposes `struct udp_pcb::recv`, `recv_arg` and `udp_pcbs`. Original [`dns.c` L973-997](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/core/dns.c#L973-L997) registers its private `dns_recv()` through `udp_recv(pcb, dns_recv, NULL)`. An isolated test can capture the PCB pointer from the **intercepted** DNS query, then inject a bounded, synthetic DNS reply `pbuf` by calling that original PCB's `recv` function **on the real TCPIP task**, supplying a synthetic source IP matching the configured server. This invokes the real DNS parser → `dns_correct_response()` → `dns_call_found()` → source-confirmed `dns_requests[].found=NULL`, while bypassing native UDP/IP ingress and emitting no reply on a socket. Source: [`dns_recv` L1300-1503](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/core/dns.c#L1300-L1503), [`dns_call_found` L1041-1103](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/core/dns.c#L1041-L1103). Response construction must satisfy matching transaction ID, question/QTYPE/QCLASS, response flag, server source, answer shape and pbuf ownership; injected `pbuf` is consumed/freed by SDK. `dns_correct_response` may remove/free the PCB during callback: **do not dereference the captured PCB after calling its recv function**.

A6b's 3/3 existing Linux SDK run proves generic core task/fence ordering but not DNS ownership. The internal `dns_requests[]` array is static/private: source confirms clear-after-callback, and externally observable re-registration/callback scheduling is a cross-check, **not a direct runtime read of private found=NULL**. Reuse/free safety requires separate affirmative proof; no inferred production reclamation.

If a synthetic reply is too intrusive/unavailable, the natural SDK timeout via `dns_tmr()`'s timer can invoke `dns_call_found(idx,NULL)` through an actual SDK timer without injecting an ingress pbuf. **Do not manually call `dns_tmr()` in a fast loop** under `ESP_LWIP_DNS_TIMERS_ONDEMAND`: [`dns.c` L443-476](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/core/dns.c#L443-L476) can schedule additional timers. ## Strict zero-egress gate (must pass BEFORE DNS registration)

- **Prebuild:** use pinned SDK and generated Linux `sdkconfig`; inspect effective `LWIP_DNS_SECURE`, `DNS_TABLE_SIZE`, core-locking/thread checks, mailbox size, `ESP_LWIP_DNS_TIMERS_ONDEMAND`, and DNS IPv4/IPv6 behavior. Check whether C compiler / LTO / linker mode honors `--wrap=udp_sendto` on the actual `dns.c` reference. Linker symbol existence is insufficient; require an actual relocation/map/disassembly-level proof that `dns_send` routes to the wrapper, and a controlled wrapper-only smoke before any DNS registration. If effective interception cannot be shown, **STOP before calling resolver**.
- **Runtime:** no `netif_add` / active netif, native sockets, real DNS packets, actual interface, TLS, Wi-Fi, credentials, QEMU, hardware or new dependencies; assert no live `netif_list` (or STOP). `__wrap_udp_sendto` records every packet attempt to bounded in-memory evidence and never forwards. Require `wrapped_count>0` in the genuine registration test, no untracked native output path from this fixture, and strict failure/timeout outputs. A real query is formed *internally*, but **no DNS query may leave the test process**; this is not a claim of end-to-end OS-wide networking interception.
- **Receive:** crafted DNS packet exists only in RAM. It enters the genuine registered `dns_recv` function via `udp_pcb::recv`, bypassing IP/UDP receive demultiplexing. Label `SDK_DNS_HANDLER_RUNTIME` or equivalent, never full-network DNS `RUNTIME_CONFIRMED`. Test suite must distinguish direct in-memory injected response from natural timeout path and explain what was not exercised.

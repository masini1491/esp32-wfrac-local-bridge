## Accepted cost-control contract (design; implementation still Codex)

- One cheap, always-emitted **PR scope-plan** job using platform GitHub PR changed-file API with pagination or an equivalent verified first-party mechanism. Cover `filename` and `previous_filename` for renames, mixed deltas union, deletes, missing/unsupported data, and not just the latest single commit. Gate unknown code paths conservatively. No third-party path filter requirement, tokens read-only `contents:read` / `pull-requests:read`; no `pull_request_target` checkout of untrusted PR.
- Execution profile: `tests/espidf_dns_probe/**` only → Linux A7b + cheap scope/summary + Host; `tests/espidf_linux_probe/**` only → Linux A6b + cheap jobs + Host; `tests/espidf_probe/**`, `components/**` or `firmware/**` → six C3/C6 builds + cheap jobs + Host; mixed → union. Pure `TASKS.md`, `BACKLOG.md`, `evidence/**`, `docs/**`, `README.md`, `specs/**`, `tests/host*/**`, `tools/validate_contracts.py` → Host (and scope) only. Pure CI workflow routing changes **may use existing 6/6 accepted evidence** if the compile commands/configs/target matrix/pinned SDK are independently shown unchanged; do not auto-run the entire matrix just to check its gate routing. If the workflow materially changes compilation/testing semantics, require full matrix before accepting. Unknown implementation-related file → full affected matrix or STOP for review; never silently classify as docs.
- PR checks remain emitted to avoid workflow path filter pending status when required; heavy jobs can be conditional and marked **SKIPPED (NOT_RUN)** in an always-visible summary. A skipped job's GitHub `success` conclusion **does not mean** tests ran. The summary must fail if a suite is selected but its job failed, was unexpectedly skipped, absent or cancelled; `always()` semantics and `needs` propagation must be explicitly tested. Avoid new job names duplicating required names accidentally and verify branch protection/check rules, if accessible; API currently returned 403 for branch protection, and ruleset endpoint reported private-tier unavailable. Record UNVERIFIED if still inaccessible.
- `concurrency` scoped by `github.workflow` and PR identity, `cancel-in-progress` true for PR only. Do not cancel unrelated manual/full runs or other workflows. Prefer removing `push(main)` triggers from these two workflows to prevent postmerge duplication **only if** required-check/release criteria permit; always preserve `pull_request` and documented `workflow_dispatch` full verification. On PR where full before merge is required, an approved `pull_request` label route (e.g. `ci/full-matrix`, with `labeled` event support) is preferable to relying on manual `workflow_dispatch` to satisfy a protected branch's required check. Manual dispatch on a PR ref is diagnostic evidence, not automatically a PR required-check result.
- Keep existing firmware commands and A5 copy/report/symbol checks, all six target/variant cells, pinned `espressif/idf:v6.0.2` SHA checks, A6b/A7b real Linux SDK probe guards, and existing Host test commands **unchanged**. Disable no fixture/test/case to make an apparent PASS. An optional explicit `workflow_dispatch` mode must select intended tests without silent fallback to `full`.
- Tests: local/offline deterministic selector matrix (dns-only, a6-only, C3/C6 component/firmware/A5, mixed, docs/coordination/Host, workflow-only CI routing, unknown, rename/delete, GitHub API pagination/error, label/manual full), workflow YAML/actionlint syntax if available, `git diff --check`, and changed-file scope. No increase to GitHub-hosted Actions on this planning task. For CI-OPT-001 draft PR, new selective workflow may run only cheap routing/Host checks, **not all six expensive firmware/A5 jobs** unless separately authorized after reviewing remaining budget. If selective routing unexpectedly fans out, STOP and, within given authority, cancel the wrong run; do not retry blindly.
- Independent acceptance requires actual scope-plan/job logs, correct skip semantics, historic six-cell evidence reuse only for byte-identical unchanged build-related inputs, CI-tested checkout/ref/tree and limited CI consumption, plus user approval before PR integration. Postmerge main Git tree must be compared against tested merge-ref; no automatic `main` status is invented. Safe default while required-check visibility is unresolved: do not advertise an automatic branch-protection guarantee; human independent review remains mandatory.

## Public platform sources / grounded constraints

- GitHub [job billable time](https://docs.github.com/en/actions/how-tos/monitor-workflows/view-job-execution-time) rounds private hosted job minutes and exposes Usage page.
- GitHub [skipped required checks](https://docs.github.com/en/pull-requests/how-tos/merge-and-close-pull-requests/troubleshooting-required-status-checks): entire workflow skip via path filter/commit message may leave required Pending; condition-skipped job may report Success; `workflow_dispatch` generally cannot satisfy PR required status checks.
- GitHub [concurrency](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency) can cancel obsolete PR runs.
- GitHub [runner minutes billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions): private hosted minutes draw from owner quota; self-hosted is not billed as hosted runner minutes, but self-hosting not included in CI-OPT-001 implementation.

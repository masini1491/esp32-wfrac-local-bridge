## 2. Current repository architecture — directly checked

- [Portable transport](../../components/wfrac_transport/include/wfrac_transport/transport.hpp) gives synchronous `ITransport::perform`, borrowed endpoint host/path/body and caller-owned output, plus a single `timeout_ms`. Views/backing storage must remain valid throughout synchronous call. It has no cancel token, async completion or owner-fence result. **CONFIRMED_LOCAL**.
- [ESP-IDF HTTP adapter](../../components/wfrac_transport_espidf/src/esp_http_transport.cpp) creates **stack-local `ResponseCollector`**, passes its address in `client_config.user_data` as `HTTP_EVENT_ON_DATA` callback context, assigns network `timeout_ms`, calls **blocking** `esp_http_client_perform` exactly once, then `esp_http_client_cleanup`; failure path collects TLS diagnostics before cleanup. It does not maintain a monotonic global attempt budget, retain an operation after the caller returns early, or wait on a separate callback-quiescence receipt. Redirect/auth retries/keepalive are disabled. **CONFIRMED_LOCAL**. Existing one synchronous call is not proof of bounded total return.
- [Request executor](../../components/wfrac_client/src/request_executor.cpp) performs one transport call for selected scheme; **if** external policy explicitly returns `retry_http_compatibility`, it may perform a second HTTP compatibility attempt using the same body. It does not itself have an aggregate `T_total` budget or propagate remaining time to each attempt. Project classifier intentionally never emits `scheme_mismatch` automatically; the two-attempt contract still exists for future compatible implementations. **CONFIRMED_LOCAL**.
- [Runtime orchestrator](../../components/wfrac_client/include/wfrac_client/runtime_orchestrator.hpp) and [implementation](../../components/wfrac_client/src/runtime_orchestrator.cpp) use caller monotonic time and check deadline **before/after synchronous execution**. Comments explicitly say this is *not preemptive*, late observations stay authoritative and report timed-out. Not a scheduler/worker task. **CONFIRMED_LOCAL**.
- Architecture/TLS policy [docs/architecture.md](../../docs/architecture.md), [TLS transport](../../docs/references/topics/tls-transport.md): current implementation only source/compile validated for real ESP-IDF WF-RAC/TLS, diagnostic firmware has separate compile-only exceptions. These existing project restrictions remain.

## 3. Pinned public API source facts (no runtime claim)

- `esp_http_client_config_t.timeout_ms` is documented as **network timeout** (0 defaults to 5s) and `esp_http_client_set_timeout_ms` sets the stored timeout. `esp_http_client_fetch_headers` performs transport reads inside a loop with per-call timeout; the timeout value cannot alone certify a whole *connect + TLS + HTTP request + response + cleanup* deadline. [pinned esp_http_client.h](https://github.com/espressif/esp-idf/blob/7101770dc6db2667b3c477cc31365dd1acd6db4e/components/esp_http_client/include/esp_http_client.h), [pinned implementation](https://github.com/espressif/esp-idf/blob/7101770dc6db2667b3c477cc31365dd1acd6db4e/components/esp_http_client/esp_http_client.c). **CONFIRMED_UPSTREAM**.
- Public `is_async` documents nonblocking `esp_http_client_perform` with `EAGAIN/EINPROGRESS` continuation, **but the pinned header explicitly says 'only supported with HTTPS for now'**. Therefore no valid inference that legacy plain HTTP enjoys equivalent async control on this pin. A cooperative HTTPS loop still needs fresh proof that each individual SDK operation and cleanup fits a remaining deadline, and single-handle concurrent calls are expressly forbidden. **CONFIRMED_UPSTREAM / hard-bound UNKNOWN**.
- Pinned `esp_http_client_cancel_request` **closes the current transport then attempts reconnect** using the same client handle, conditional on state; it is not a documented cross-thread cancellation, callback-drain or safe retirement primitive. **CONFIRMED_UPSTREAM**.
- Pinned `esp_http_client_cleanup` calls `esp_http_client_close`, ignores the close return value in that function, frees client data/handle and returns `ESP_OK`; `esp_http_client_close` dispatches a disconnected event and calls `esp_transport_close` in a conditional state. The public cleanup API provides no independent proof here that *all* TCPIP/TLS/HTTP callbacks/PCBs are globally reclaimed in finite time. This is a source-review **observability limit**, not proof of an actual leak/UAF in normal synchronous use. **CONFIRMED_UPSTREAM / runtime safety UNKNOWN**.
- The preexisting R2-C0 source review shows `lwip_close` may return `-1` or `0`; lower TCP FIN `ERR_MEM -> TF_CLOSEPEND` may still lead to API-level success. Pinned lwIP `tcpip_send_msg_wait_sem` may use `sys_arch_sem_wait(sem,0)` on non-core-locking paths, with no universal caller-return bound. Neither a short R2-C2 observation nor upstream internal timeout establishes a hard caller/cleanup deadline. [R2-C0 study](stage3-gatea-r2c-close-abnormal-observability-source-20261019.md). **CONFIRMED_UPSTREAM / abnormal Runtime NOT_OBSERVED**.

## 4. Gate A L1/L2/L3 contract audit

| Layer / admission target | Current status | Safe but limited capabilities | Missing evidence to promote |
| --- | --- | --- | --- |
| **L1 monotonic *aggregate* deadline for one logical operation** | **PARTIAL / NOT PROVEN** | Caller monotonic start/deadline, remaining-budget checks before/after calls, fail closed on elapsed time, budget propagation can be designed; IDF has network timeout and HTTPS-only async mode | Guaranteed upper bound on each opaque SDK step (DNS/connect/TLS/request/response/cleanup), combined with optional scheme fallback, proven against callback and clock edge cases; no blocked sync call may outlast bound |
| **L2 single physical attempt / no overlapping in-flight work** | **PARTIAL / NOT PROVEN** | One synchronous `ITransport::perform` per physical attempt, explicit bounded policy decisions; test-only owner retention on unresolved close; prohibit new requests while physical state unknown | An enforceable cancellation/termination or quarantine/recovery contract with true in-flight/retired provenance; safe handling of worker stuck indefinitely without claiming resource free; logical request may use 2 attempts per policy |
| **L3 safe owner and SDK lifecycle / cleanup evidence** | **APPLICATION MODEL PARTIAL / SDK NOT PROVEN** | R2-A/R2-C1 synthetic retention; R2-B/R2-C2 narrowly observed callback barrier + socket return and logical release | Publicly valid receipt that HTTP handle, response collector, TLS, task/worker, all SDK callbacks and close/cleanup have actually ceased and may be physically deallocated within bound; absence of PCB/global quiescence cannot be inferred from `close==0` or barrier ACK |

**Necessary distinction:** (A) *request-result deadline* means caller reports `timeout` by deadline; (B) *physical attempt termination deadline* means the underlying network/TLS/SDK work actually stopped; (C) *resource-safe cleanup deadline* means all owners/borrows/callbacks may be reclaimed. Existing synchronous code does not even guarantee (A) when it blocks inside `perform`; an external watcher could bound a supervisor's *notification* but cannot automatically establish (B)/(C). A test that retains every unresolved owner is safer but risks unbounded retention. **Do not redefine Gate A from strict A+B+C to 'soft timeout observed' without an explicit user/architecture decision.**

## 5. Options and cost/benefit recommendations (analysis, not execution)

1. **Option S — retain synchronous adapter and label it soft/observed-only:** lowest change/risk, preserves existing portable interfaces and TLS/legacy scheme policy. Pre/post monotonic checks and honest timeout classification are valid, but no hard aggregate caller bound, cancellation or cleanup guarantee. **Viable only if product accepts that limitation; not sufficient for strict Gate A.**
2. **Option H — HTTPS cooperative async via public `esp_http_client`:** promising bounded-step prototype for HTTPS because `is_async` is publicly documented, requires API/compile test and real source semantics per individual stage incl. cleanup and callback lifetime. **Plain HTTP unsupported by stated async contract**; dual-scheme support, TLS trust and remaining budget need separate design. Cannot claim strict hard completion until all blocking edges and retiring resources are proven.
3. **Option P — public low-level stepped HTTP/socket/TLS with deadline-aware owner:** may be architecturally feasible for both schemes, but substantial replacement of HTTP framing, async TLS, response parsing and error handling. Existing certified policy/code must not be silently copied/rewritten; DNS and TLS teardown need independent evidence; the pin's public API does not currently establish strict end-to-end bound. **Research candidate, not recommendation to implement immediately.**
4. **Option W — worker + watchdog + quarantine:** can potentially bound supervisor *notification* while worker remains blocked. To avoid stack-local `ResponseCollector` and borrowed input UAF, all request/response/certs/client context must be worker/owner-retained; no new attempt or freed state until completion. If no completion ever arrives, owner and worker may be retained indefinitely. **Not a proof of L2 physical termination/L3 cleanup; do not treat as strict Gate A solution.**
5. **R2-C3 forced `ERR_MEM`/private PCB/SDK source patch:** not admitted and unlikely to solve the general HTTP/TLS total deadline architecture by itself. Do not automatically launch.

**Next lowest-risk decision:** resolve the product meaning of *hard timeout*: whether `D_result` (caller notification) is sufficient while unfinished resources are quarantined, or whether Gate A requires `D_physical` and `D_cleanup` within the same finite budget. For the currently claimed strict total-attempt objective retain **all three as UNSATISFIED** until explicitly changed. If strict is retained, the next test-only candidate is a scoped **GATEA-D2 public-API edge inventory/compile-only feasibility matrix** for HTTPS async vs legacy HTTP, with independent cancellation/cleanup life-cycle evidence; no new socket runtime/fault injection. This is a **proposal pending separate execution authorization and a safe clean-main workspace**, not an executable child under this study's consent.

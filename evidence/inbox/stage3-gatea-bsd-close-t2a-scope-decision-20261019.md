## Technical delta over T1 — actual supported application socket API

- Pinned [`lwip_socket()` in sockets.c L1729–1787](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/sockets.c#L1729-L1787) constructs an actual netconn and allocates a socket-table descriptor. A *never-bound, never-connected* `lwip_socket(AF_INET, SOCK_STREAM, IPPROTO_TCP)` is a candidate for an isolated, no-network-output Linux SDK fixture, subject to actual generated `LWIP_SOCKET`, IPv4, lwIP and no-netif configuration. Source study is not proof the fixture successfully compiles/executes in the pinned Linux target.
- Pinned [`lwip_close()` L817–855](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/sockets.c#L817-L855) calls `netconn_prepare_delete()`; on non-`ERR_OK` it sets errno and returns -1 **without** calling `free_socket()`. On `ERR_OK`, it performs `free_socket()` then returns 0. This is more application-relevant than T1's direct `netconn_delete()`; however a successful unconnected close is **not** proof of connected FIN allocation, socket-owner failure recovery, or global L3.
- [`free_socket_free_elements()` L615–630](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/sockets.c#L615-L630) calls `netconn_delete()` after `netconn_prepare_delete()` to dispose the final connection object. Depending on `LWIP_NETCONN_FULLDUPLEX` and actual path, this can create a further TCPIP API-message completion boundary; exact post/sem count must be **observed**, not hard-coded from T1. [`api_lib.c` L195–257](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/api_lib.c#L195-L257) shows both phases.
- In pinned non-core-locking lwIP, [`tcpip_send_msg_wait_sem()` L442–465](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/tcpip.c#L442-L465) posts an API message and waits with `sys_arch_sem_wait(sem,0)`; `lwip_close()` does not thereby acquire a universal caller-return bound. Explicit release of a test-only blocked TCPIP callback can demonstrate owner retention until actual completion, not permanent-stall reclamation.
- The current [isolated Linux T1 fixture](../../tests/espidf_linux_probe/README.md) already requires `netif_list==nullptr`, disabled loopback, unchanged SDK linkage, finite gates, static retained owner, and external test watchdog. T1 observed real `netconn_delete()` only, not `lwip_close()`. Link-time `sys_mbox_post` / `sys_arch_sem_wait` observers delegate to unchanged SDK functions. A future socket fixture can reuse these controls without fake SDK results; do not invent a new production worker or open an actual TCP connection.

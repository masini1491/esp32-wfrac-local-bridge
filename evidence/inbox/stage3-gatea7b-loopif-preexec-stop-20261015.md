## Source-confirmed root cause / correction

- Pinned [ESP-IDF v6.0.2 `components/lwip/Kconfig` L569-576](https://github.com/espressif/esp-idf/blob/7101770dc6db2667b3c477cc31365dd1acd6db4e/components/lwip/Kconfig#L569-L576): `CONFIG_LWIP_NETIF_LOOPBACK` default `y`; pinned [port `lwipopts.h` L797-820](https://github.com/espressif/esp-idf/blob/7101770dc6db2667b3c477cc31365dd1acd6db4e/components/lwip/port/include/lwipopts.h#L797-L820) maps enabled option to `LWIP_HAVE_LOOPIF=1`, `LWIP_NETIF_LOOPBACK=1`, but disabled to `LWIP_HAVE_LOOPIF=0` (and upstream `LWIP_NETIF_LOOPBACK` default zero). The observed Linux binary prints both enabled.
- Pinned [esp-lwIP `lwip_init()` L352-388](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/core/init.c#L352-L388) calls `netif_init()`. [`netif.c` L135-215](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/core/netif.c#L135-L215) has built-in software loopback `loop_netif`, names it `lo`, assigns `127.0.0.1`, registers through `netif_add()` and marks up/link up, solely when `LWIP_HAVE_LOOPIF`. Thus `netif_list!=nullptr` is expected even with no external interface or real DNS output. The fail-closed guard is **over-strict for the unmodified SDK default**, not evidence of packet egress.
- Correct within the *already authorized A7b test-only scope*: change **only isolated** `tests/espidf_dns_probe/sdkconfig.defaults` to include disabled option `# CONFIG_LWIP_NETIF_LOOPBACK is not set`, retain existing `CONFIG_LWIP_ENABLE=y`; ensure newly generated `build-a7b/sdkconfig` really reports `# CONFIG_LWIP_NETIF_LOOPBACK is not set` and runtime macros `LWIP_HAVE_LOOPIF=0`, `LWIP_NETIF_LOOPBACK=0`. Preserve exact `netif_list==nullptr` fail-closed checks and wrapper-only smoke. Update test-only runner/README/CI verification only if required to assert this premise. Do not change SDK, A6b, six C3/C6 configs, production, actual DNS/UDP networking permission, or TLS/hardware.
- Disable-loopback proposal is **SOURCE_SUPPORTED / UNTESTED**: actual Kconfig propagation, binary linkage, smoke, negative guard and DNS cases remain unverified. If reconfiguration does not result in null netif or any output guard fails, STOP rather than widening guard. No approval to merge PR #12 or to remove no-network constraints.

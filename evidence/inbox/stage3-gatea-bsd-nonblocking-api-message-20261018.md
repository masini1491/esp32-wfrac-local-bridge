Read-only research, with no new SDK test, task/worker implementation, hardware/network execution, source/SDK/workflow mutation or Gate B admission. ## New upstream call-path findings

1. **`O_NONBLOCK` does not bound initial TCPIP API-message dispatch.** Pinned `lwip_fcntl(F_SETFL)` toggles the netconn nonblocking flag ([`sockets.c` L3918–3982](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/sockets.c#L3918-L3982)). However, even for this socket, `lwip_connect()` calls `netconn_connect()` ([`sockets.c` L858–914](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/sockets.c#L858-L914)); `netconn_connect()` calls `netconn_apimsg(lwip_netconn_do_connect,...)` ([`api_lib.c` L379–402](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/api_lib.c#L379-L402)), which calls `tcpip_send_msg_wait_sem()` ([L117–139](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/api_lib.c#L117-L139)). In the pinned **non-core-locking** configuration that last function calls `sys_mbox_post()` and then `sys_arch_sem_wait(sem,0)` ([`tcpip.c` L441–465](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/api/tcpip.c#L441-L465)). The ESP-IDF port maps these operations to FreeRTOS `portMAX_DELAY` waits; see [`sys_arch.c`](https://github.com/espressif/esp-idf/blob/7101770dc6db2667b3c477cc31365dd1acd6db4e/components/lwip/port/freertos/sys_arch.c#L156-L188). **Interpretation:** nonblocking socket connect can return `EINPROGRESS` from the TCP connection state machine, but that return is reached only *after* an initially synchronous, unbounded TCPIP dispatch/wait. This is a source-level absence of a universal caller-return proof, not an observed permanent stall.
2. **An async DNS found callback is not a public per-request cancel primitive.** Pinned [`dns.h` L106–115](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/include/lwip/dns.h#L106-L115) exposes `dns_gethostbyname[_addrtype]`, cache clear and server APIs, but no matching public `dns_cancel(request_id)`. Pinned [`dns_clear_cache()` L405–419](https://github.com/espressif/esp-lwip/blob/fd432e4ee2cfb7f7f1c7eb7227e0173412e7b84e/src/core/dns.c#L405-L419) iterates all active DNS entries, dispatches `dns_call_found(idx,NULL)` and clears the global DNS table. It must **not** be treated as safe single-request cancellation; callback ownership, other requests and global cache semantics would change. Accepted A7b finite generation reuse remains scoped to *completed callback+deferred fence*, not an arbitrary never-completing request.
3. **TLS readiness is not full network/cleanup quiescence.** Pinned [ESP-TLS mbedTLS backend](https://github.com/espressif/esp-idf/blob/7101770dc6db2667b3c477cc31365dd1acd6db4e/components/esp-tls/esp_tls_mbedtls.c#L268-L315) handles `mbedtls_ssl_handshake()` returning `ESP_TLS_ERR_SSL_WANT_READ/WRITE`; [certificate config](https://github.com/espressif/esp-idf/blob/7101770dc6db2667b3c477cc31365dd1acd6db4e/components/esp-tls/esp_tls_mbedtls.c#L540-L558) configures `MBEDTLS_SSL_VERIFY_REQUIRED`, and [hostname setup](https://github.com/espressif/esp-idf/blob/7101770dc6db2667b3c477cc31365dd1acd6db4e/components/esp-tls/esp_tls_mbedtls.c#L916-L938) calls `mbedtls_ssl_set_hostname()`; disabling the common name check in the pinned backend also disables hostname matching/SNI. **Design implication only:** manually controlling TLS over a separately resolved IP would have to retain original host identity/SNI, certificate verification and compatible PEM trust. It does not make `socket close`, DNS lifetime or scheduler completion bounded, and has not been implemented or tested here.
4. **Core-locking is not a free cancellation route.** The pinned `tcpip_send_msg_wait_sem()` uses a TCPIP core mutex when `LWIP_TCPIP_CORE_LOCKING=1`, instead of queue/semaphore completion; the lock acquisition itself has no per-attempt hard timeout proof. Changing Kconfig solely to remove mailbox waits is not admitted by this research.

## Stage 3 Gate A feasibility verdict

| Segment | Candidate progress | Unproven condition |
| --- | --- | --- |
| DNS name resolution | Async callback + static-owner completion fence previously exercised (A7b) | Safe per-request cancellation/finite release if callback never completes |
| Nonblocking TCP connect | Supported BSD sockets; `O_NONBLOCK` and readiness state after dispatch | TCPIP message admission/completion caller-return hard bound, including stuck TCPIP thread |
| TLS handshake / verified hostname | Source-level mbedTLS WANT_READ/WRITE and verification mechanics | Hard deadline across every TLS call, no verification downgrade, teardown and socket release |
| HTTP transfer / trickle peer | Explicit monotonic aggregate budget can be architected | No unbounded subcall and correct handling of possible-delivered writes |
| TCP close / TLS cleanup | Earlier CLOSED-only T1 conditional completion + F1 synthetic error masking | Connected FIN/ERR_MEM, close-error disposition, callback quiescence, arbitrary stall reclamation |
| Scheduler and watchdog | No new evidence | Universal wall-clock caller-return and availability under scheduler or TCPIP stalls |

**Conclusion:** A supported BSD sockets + controlled TLS rewrite is **a research candidate, not an admitted solution** to the original universal synchronous D0 L1/L2/L3. In fact the initial nonblocking TCP connect is a *newly explicit synchronous lower-layer wait boundary*. Do not implement a production prototype, change pinned SDK/Kconfig, launch test-only cases, or adopt `dns_clear_cache` or task deletion as cancellation without a separate task/architecture authorization.

**Next decision:** Either explicitly retain the strict all-layer deadline and demand a cancellable/schedulable TCPIP+TLS+resolver/teardown architecture with independently measurable quiescence, or separately authorize a narrowed fail-closed supervisor contract (caller-visible deadline, finite permanently occupied slots, degraded availability, no universal cleanup claim). Merely adding bounded `select()` waits, toggling `O_NONBLOCK`, or repeating T1/F1 cannot close the remaining proof obligations.

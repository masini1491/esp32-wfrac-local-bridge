## 1. Threat and claim boundary

- **Future runtime objective only:** one signed-off Linux x86-64 ELF, six synthetic witnesses (3 kinds × HTTP/HTTPS), no attempted or successful network egress by the fixture or descendants, including loopback, IPv4/IPv6, DNS (UDP/TCP), Unix sockets to other processes, built-in SDK TCP/SSL transport, and alternate kernel I/O routes. An attempted forbidden syscall is a **hard failing witness**, even if no traffic escaped.
- Scope includes dynamic loader/shared libraries, libc, raw `syscall()`, inherited file descriptors, environment, compatible/alternate syscall ABIs, `io_uring`, process/namespace escape and child processes; it excludes production firmware/network correctness and real TLS identity. This is a bounded test of a synthetic SDK witness, **not** an acceptance of Gate A L1/L2/L3, HTTPS certificate/SNI/hostname checks, real socket lifecycle or event-queue quiescence.
- Source inspection, linked symbols, `--network none` / network-namespace emptiness **alone**, zero observed packets, or a successful JSON result **alone** never prove enforcement. The enforcement and negative-control proof must be independently reviewable before the target's first instruction executes.

## 2. Proposed mandatory layered guard (design, not deployed)

A **trusted outside supervisor** owns input hashes, policy compilation/verification, child creation and wait-status evaluation. The target and its loader run **only inside a fresh disposable sandbox**. A possible future namespace/mount helper is locally verified `bubblewrap` (rootless user + network + PID + IPC/UTS namespaces, fixed minimal read-only mounts, `--die-with-parent`, `--new-session`, no privileged mode or ignore-sandbox-failure setting); this is a design candidate, **not an assertion it is installed or works in WSL**. A purpose-built equivalent must receive a fresh design review; lack of namespace or seccomp capability = STOP, no permissive fallback, Docker substitute, host socket tests or permission workaround.

A future authorized launcher must enforce the following **before the target ELF executes**:

1. **Identity and immutable inputs.** Freshly verify the actual Git repo, branch, worktree and parent revision, exact five committed candidate blobs, build provenance, ELF bytes and SHA-256 (from the independently audited corrective handoff, when materialized), architecture (`ELF64 x86-64`) and dynamic dependencies, approved sandbox profile bytes/SHA-256, guard binary/hash and kernel/runtime capabilities. Do not infer an ELF hash from source SHA; if the exact ELF or dependent libraries are missing or hashes disagree, STOP. Preserve original evidence; no automatic rebuild, network download or new build authority.
2. **Isolated filesystem and host capabilities.** Use an ephemeral Linux-native directory, minimal pinned read-only executable/loader/library contents, no host `/mnt/c` or home bind, no network resolver sockets, secrets, Git credentials or project-wide mounts, and only bounded tmpfs for scratch. Require a distinct empty network namespace; verify namespace inode differs from host, no external veth/routes, loopback not enabled as a way to escape; no inherited sockets. A separate PID namespace and parent-death containment must prevent orphaned children. Deny namespace changing, mounts and privilege escalation after setup.
3. **Privileges, env and descriptors.** Clear environment and supply a literal allowlist (e.g. minimal `PATH`, `LANG=C`, `HOME` pointing at private tmpfs); remove `LD_PRELOAD`, `LD_AUDIT`, proxies, resolver/credential and repository-specific environment inputs. Run with no effective/permitted/ambient capabilities, fixed UID/GID, `NoNewPrivs:1`, core dumps disabled, and no preexisting ring, socket or host IPC descriptors. Establish supervisor-owned 0=/dev/null and 1/2=capped log pipes; close/unshare all descriptors >=3 before target `execve` (verified `close_range(..., CLOSE_RANGE_UNSHARE)` or a separately accepted exact equivalent) except a strictly scoped setup-only FD, which **must** close before the ELF. Verify the actual child's `/proc/<pid>/fd` and FD types, not only the supervisor's. Never inherit an `io_uring` FD or network-capable socket.
4. **Kernel seccomp-BPF allowlist.** Install before `execve`, after `PR_SET_NO_NEW_PRIVS=1`, with a signed/hashed **exact installed filter bytes** and explicit `AUDIT_ARCH_X86_64` ABI check. Reject other architectures and the x32 syscall-number high bit; no silent compat-ABI fallback. Default for every unknown syscall is **`SECCOMP_RET_KILL_PROCESS`**, not `ALLOW` or a silent `ERRNO`. The exact allowlist for pinned libc/loader and fixture must be enumerated and audited before implementation acceptance; no learned-at-runtime automatic additions. Block every socket/connect/listen/bind/accept/send/receive family (also `socketpair`, raw/compat `socketcall`), `io_uring_setup/enter/register`, `fork/vfork/clone/clone3`, `setns/unshare`, `bpf`, `ptrace`, `perf_event_open`, mount/namespace mutation and other privileged/FD or communication escapes unless a specific verified exception is independently admitted. Audit other mechanisms (`openat`, `sendfile`, `splice`, `writev`, `SCM_RIGHTS`, `ioctl`) against the FD + read-only mount policy. Explicitly disallow an existing `io_uring` ring. An incomplete syscall or architecture inventory is a design/implementation blocker.
5. **Effective-state attestations, outside the target's control.** Before target start, the supervising process independently verifies child UID/GID, CapEff/CapPrm/CapAmb, `NoNewPrivs`, `Seccomp:2` and filter count, namespace IDs, network interfaces/routes, FD inventory and types, mount and environment allowlists. `/proc/<pid>/status` confirms mode, **not actual seccomp filter equality**; independently bind the exact installed filter creation path to the policy SHA and corroborate with negative controls. Do not rely on an unauthenticated JSON string printed by the target to attest its own sandbox.

**Startup order:** immutable input/hashes → pre-exec isolation/capability/FD/policy checks → separate negative-control processes under the same policy bytes and sandbox parameters → independently check each receipt → only after a **future separate user runtime authorization** allow the fixture's one bounded launch. The current task stops at design.

## 3. Negative controls (future separate authorization only; never run unguarded)

Each control is a separate synthetic probe executable, with a separately verified SHA-256, in a fresh sandbox using the **identical immutable seccomp policy bytes**, architecture, environment, resource/FD and namespace parameters planned for the fixture. No probe reaches a real network; expected verdicts are supplied by trusted supervisor wait-status evidence:

| Control | Expected kernel behavior | Verifier |
| --- | --- | --- |
| `socket(AF_INET, SOCK_STREAM, ...)` / `socket(AF_INET6, SOCK_DGRAM, ...)` | Forbidden at syscall entry | Target process SIGSYS / `KILL_PROCESS`; no socket created |
| `socket(AF_UNIX, ...)`, `socketpair(...)` | Forbidden local IPC endpoint creation | SIGSYS, not a harmless `EPERM` that a fixture might ignore |
| raw `connect(-1,...)`, `sendto(-1,...)`, `sendmsg(-1,...)`, `recvfrom(-1,...)` | Forbidden **even on invalid FD**, before kernel argument/fd validation | SIGSYS, not merely EBADF; validates direct syscall path without real socket |
| `io_uring_setup`, `io_uring_enter`, `io_uring_register`, `setns`, `clone` | Forbidden alternate I/O / namespace / process routes | SIGSYS |
| x32-bit syscall-number / disallowed ABI attempt | Forbidden by architecture gate | SIGSYS where safely testable; otherwise design blocker requiring equivalent reviewed proof |
| Policy missing, altered hash, unrecognized FD, namespace creation denied or environment not cleared | No probe/fixture target spawn | Supervisor `PRE_EXEC_STOP` with exact reason; no unguarded syscall negative probe |

A normal exit, `EPERM`, `EBADF`, killed-by-something-other-than-SIGSYS, missing control, uncontrolled stderr, or a guess based on an outer wrapper's numeric exit code is **not** a successful forbidden-syscall control. Verify `waitid`/`waitpid` signal semantics or a proven wrapper propagation, bound output/time, and produce an individual receipt per probe. DNS-library behavior cannot be inferred merely from `getaddrinfo(\"fixture.invalid\")` because resolution might be satisfied without a socket; synthetic UDP/TCP socket and raw-send probes are the compulsory DNS-egress primitive controls.

## 4. Future fixture verifier and fail-closed receipt

**Proposed design limits, not measured facts:** a single fixture launch with a 30-second outside wall-clock watchdog; each probe ≤3 seconds; bounded stdout/stderr ≤64 KiB total; no core dumps; bounded memory/process count. Exact kernel/loader constraints and limits require offline capability review before implementation.

An independent outside verifier requires **all** of:
- Input source Git blobs 5/5, SDK pin, ELF/dependencies and guard/policy hashes match authorized manifest; pre-exec receipts verified and **all** mandatory negative controls passed with the same policy.
- Target's genuine raw wait status = normal exit 0 (not signal/timeout or wrapper-only success), **exactly six distinct** `scheme × witness` JSON case rows with `PASS`, one summary `total=6,passed=6,failed=0`; no duplicates/extra/malformed records, no synthetic oracle promoted to physical evidence.
- No forbidden-syscall `SIGSYS`, missing seccomp/policy attestation, unexpected FD/interface/namespace, unsupported ABI, overrun, uncontrolled child, unverified dependency, or reported denied egress. A block terminates the fixture and **fails the campaign**; blocked network attempts are not silently reclassified as zero-attempt success.
- Receipts must distinguish **`PRE_EXEC_STOP`** / **`GUARD_NEGATIVE_CONTROL_PASS`** / **`FIXTURE_PASS`** / **`FIXTURE_FAIL`** / **`NOT_RUN`**; include timestamp, runner + host/kernel/WSL version, parent + target PID/namespace/UID/capabilities, FD inventory, filter/guard/ELF/source hashes, every negative-control ID + signal, actual stdout/stderr hashes and byte counts, raw wait status, timeout/limits, chosen policy and exact denied attempt evidence when available. Seccomp audit log is optional corroboration—**absence of a kernel audit record is not a proof that no forbidden call was attempted**.
- Never record credentials, real WF-RAC requests or private user data. Only release non-sensitive bounded receipts. Preserve evidence without altering historical D2/D4/R1 artifacts.
